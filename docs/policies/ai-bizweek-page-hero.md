# AI BizWeek Page Hero 主圖 Instructions

## 適用範圍與資產分類

本章適用於 AI BizWeek Facebook Page 貼文用橫式商業洞察主圖。

每個圖像任務必須唯一宣告：

```yaml
asset_family: page_hero
```

`page_hero` 與 `audio_brief` 是不同資產家族。不得混用、借用、融合或推論第三種混合版型，也不得使用 Audio Brief 封面圖替代 Page Hero 主圖。

## 輸出格式

- Facebook Page 貼文用橫式商業洞察主圖。
- 實際圖片必須為精確 16:9 橫式比例。
- 必須適合 Facebook 手機閱讀，縮圖狀態下仍能先看懂核心商業啟示。
- 圖片的目的不是介紹公司，而是講清楚案例中創新的商業模式。

## Facebook Page 主圖完整規格

請依以上的案例設計一張 **Facebook Page 貼文用橫式商業洞察主圖**。

### 視覺風格要求

整體請採用：

- **米白色紙感背景**
- **黑色粗體大標**
- **高飽和藍色**作為主要強調色
- **亮橘色**作為次強調色與筆刷標記
- 可少量加入亮綠或螢光黃作重點提示
- 視覺語言像 **創業雜誌封面 + 商業筆記海報 + 漫畫編輯感資訊圖**
- 具有 **手繪箭頭、圈選、底線、筆刷、便條紙、卡片、重點標記**
- 整體感覺要有：
  - sharp
  - bold
  - insightful
  - editorial
  - social-media-friendly
- 不要做成制式企業簡報
- 不要做成 SaaS 官網 hero section
- 不要使用寫實人物照
- 不要過於工整死板，應該像「有觀點的商業分析圖」

### 文字與資訊層級

這張圖的最大重點不是介紹案例背景，而是要先傳達：

> **這個案例對 1 人公司的商業啟示是什麼**

請把資訊層級安排為：

1. **最大標：對 1 人公司的核心啟示**
2. **次重點：這個商業模式最創新的地方**
3. **中段：商業模式如何運作的流程**
4. **小型資訊卡：案例名稱、國家、創辦人、MRR、獲客方式、風險**
5. **底部：今日可做 / 可行動建議**

### 畫面內容元素

請用以下幾種元素來表達這個創新商業模式：

- **一句強而有力的核心洞察標題**
- **1–3 個被放大的關鍵詞**
- **多個需求來源或訊號來源的小卡片**
- **匯流到高意圖客戶的流程箭頭 / 流動線條**
- **一個簡單的商業模式轉換路徑**
- **案例資訊卡**
- **一個風險提醒區塊**
- **一個今日可做的行動區塊**

### 視覺表現方式

請讓畫面能一眼看出：

- 這個案例的 **創新點**
- 與傳統做法的 **差異**
- 這個模式為什麼對 1 人公司特別有價值
- 它的 **可複製啟發**

### 請特別強化以下重點

- 核心商業啟示要最大、最醒目
- 關鍵詞可用超大字、藍字、橘色筆刷、手繪底線來強調
- 案例資訊只作為佐證，不要比核心洞察更搶眼
- 圖片的目的不是「介紹公司」，而是「講清楚這個創新的商業模式」

## 案例內容與事實邊界

- 每次產製必須從該任務的 task-scoped Source of Truth 取得案例名稱、國家、創辦人、MRR、獲客方式、風險、核心洞察、流程與今日可做。
- 若案例來源沒有 MRR，必須改用來源中實際存在且可驗證的營收或核心成果欄位；不得為了填滿資訊卡而自行創造 MRR。
- 若任一欄位在案例來源中不存在，應省略該欄位或使用來源中語意相符的已驗證欄位，不得編造人物、國家、數字、比例、成效、獲客渠道或風險。
- 所有中文必須為正確、清楚、可閱讀的繁體中文與台灣用語；不得出現簡體字、亂碼或自行改寫指定文字。
- 圖片右下角或底部必須有可讀的 `AI-assisted visual` 揭露。

## 與 Audio Brief 的隔離

本政策只約束 Facebook Page Hero。

不得把以下 Audio Brief 封面固定元素套入 Page Hero：

- 1:1 正方形 Podcast 封面版型
- 深海軍藍大面積 Podcast 品牌區
- `AUDIO BRIEF` 金色標籤作為主視覺核心
- 右上 EP／國旗固定方框
- Podcast 麥克風與耳機作為主要版面
- 底部 Podcast 節目資訊列

Page Hero 的主視覺必須是橫式商業洞察資訊圖，不得退化為 Podcast 單集封面、企業簡報、SaaS 官網 Hero 或寫實人物宣傳照。

## 通用 Page Hero 驗收閘門

Grace review 必須檢查實際生成圖片，不得只審核 Prompt 或 worker 自述。

逐項驗證：

1. `asset_family` 唯一為 `page_hero`。
2. 實際圖片為精確 16:9 橫式 Facebook Page 商業洞察主圖。
3. 最大、最醒目的資訊是案例對 1 人公司的核心商業啟示，而不是公司名稱、人物、產品或案例背景。
4. 畫面包含商業模式創新點、運作流程、案例佐證、風險提醒與今日可做。
5. 米白紙感、黑色粗體、高飽和藍、亮橘筆刷及手繪編輯資訊圖語言清楚成立。
6. 不得呈現制式企業簡報、SaaS 官網 Hero、寫實人物照、過度工整排版或 Audio Brief 固定版型。
7. 案例文字、人物、國家、數字、獲客方式與風險均可追溯到 task-scoped Source of Truth；沒有新增未驗證資訊。
8. 所有中文為正確、可閱讀的繁體中文與台灣用語，沒有簡體字、亂碼或擅自改寫。
9. 交付包含實際圖片、像素尺寸、16:9 比例驗證、SHA-256、政策版本與可見的 `AI-assisted visual` 揭露。

任一項缺失、錯誤、無法判讀或未驗證時，review 必須拒絕並退回精確修正，不得以 Prompt 正確、檔案存在或 worker 表示完成作為驗收通過依據。
