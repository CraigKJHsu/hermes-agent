# AI BizWeek Facebook Page Source Fidelity Policy

## 核心規則

當 KJ 提供 Facebook Page 內文、貼文底稿、已發布貼文內容、截圖文字或完整案例正文時，該內容預設是當次 Page 交付的最高優先級 Source of Truth。

除非 KJ 已經和 Grace 明確討論並確認要修改哪些部分，否則 Grace／ClawOps 不得自行縮減、摘要、改寫、重排、合併、刪除段落、改變語氣、替換標題或重建文章架構。

預設行為是：

> 全文保留 KJ 提供的 Facebook Page 內文，僅做任務明確要求且不改變內容完整性的附加處理。

例如 KJ 只要求「整理正式交付」、「生成主圖」、「準備完整發布包」、「依 instructions 生成圖片」、「交付可貼用內容」時，不代表授權 Grace 縮短或重寫 Page 內文。

## Page 貼文固定順序

原本的 Facebook Page 貼文結構仍然正確，且不得因 Source Fidelity 規則而移除：

案例正文
↓
Page → Group 導流 CTA（如需要）
↓
案例客製化 Hash Tags（正文最後一段，貼文到此結束）

Hash Tags 是 Page 貼文正文的一部分，不是獨立交付項。若需要 Page → Group 導流 CTA，CTA 必須放在 Hash Tags 前面。Hash Tags 後面不得再放任何 CTA、說明、備註、驗收文字或其他內容。

## 允許修改的前提

Grace／ClawOps 只有在以下任一條件成立時，才可修改 KJ 提供的 Facebook Page 內文：

1. KJ 在同一任務中明確要求修改、潤稿、重寫、精簡、改標題、改開頭、調整段落或改 CTA。
2. KJ 與 Grace 已針對該篇內容討論並確認具體修改方向。
3. KJ 明確指出某段錯誤、過長、不適合或需要刪除。
4. 任務明確要求加入 Page → Group 導流 CTA 或 Hash Tags；此時只能新增或調整該指定部分，不得藉此縮減原文主體。

即使符合上述條件，修改也必須限於已確認範圍。未被討論或未被授權修改的段落，仍須逐段保留。

## 禁止事項

除非 KJ 明確授權，不得：

- 把 KJ 提供的 Page 內文改寫成摘要版。
- 只保留重點數字或幾段分析，刪除其他原文內容。
- 為了「Facebook 閱讀節奏」自行大幅縮短。
- 為了配合圖片、Podcast 或 Group 內容，重寫 Page 主文。
- 將完整 Page 內文改成模板化文章。
- 將 KJ 原文中的段落改成 AI 式總結。
- 省略 KJ 提供的例子、觀點、限制、行動建議或結語。
- 只交付「工作紀錄摘要」代替完整 Page 文字。

## Grace Review 驗收閘門

Grace review 必須把最終 Page 內文與 KJ 提供的 Source of Truth 做 source-vs-output diff。

若沒有明確修改授權，review 必須確認：

1. KJ 提供的 Page 內文主體已完整保留。
2. 未出現未授權縮減、摘要、重寫或段落刪除。
3. 若有新增 Page → Group CTA 或 Hash Tags，新增內容位於正確位置，且沒有取代原文主體。
4. 最終順序為案例正文 → Page → Group 導流 CTA（如需要）→ 案例客製化 Hash Tags，且 Hash Tags 是正文最後一段。
5. 最終交付是可直接貼用的完整 Page 內文，不是摘要、驗收紀錄或任務說明。

若有明確修改授權，review 必須確認：

1. 修改範圍與 KJ／Grace 討論內容一致。
2. 未討論的段落仍完整保留。
3. 任何刪除、合併或改寫都有對應的授權依據。
4. 最終順序為案例正文 → Page → Group 導流 CTA（如需要）→ 案例客製化 Hash Tags，且 Hash Tags 是正文最後一段。
5. 最終版本沒有添加 task-scoped Source of Truth 之外的新事實。

缺少 source-vs-output diff、修改授權不清楚、或無法確認原文是否完整保留時，Grace review 必須拒絕，不得驗收通過。
